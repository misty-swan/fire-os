予定/出欠/活動記録、点検票/施設台帳/車両、出動履歴、自由記述が分散しているという課題仮説を実団体へ確認する。FireOSは一つの共通データ基盤で関連を追跡し、地図を点検/異常対応の入口にする。Jevが分類候補、LLMが下書き、承認済文書の検索が根拠を提供し、人の権限/承認を経て業務へ接続する。

| 利用者 | 想定責務（承認待ちD03等） |
|---|---|
| 一般団員 | 本人出欠、予定/許可地図/連絡、点検/異常報告、自分の実績確認 |
| 班長/担当者 | 担当活動/点検/資機材/一次確認、割当範囲の記録 |
| 幹部 | 運営/実績/出動記録の統括と許可された承認 |
| システム管理者 | 招待/停止/技術設定/監査/運用。機微情報全文の無条件閲覧権ではない |
| 自治体/情報保有者 | 利用許諾、台帳/帳票/個人情報/正式連絡の規程確認 |

成功は個別CRUD数でなく、予定→出欠→実績→承認帳票、施設→点検→異常→タスク/通知、出動→参加/帰還→活動/使用資産、文書→根拠付き検索が同じ権限と履歴でつながること。AI-06/07/MAP-10の採用区分はD01、設計/試験を保全し未決のまま除外してリリースしない。利用者の操作成功、AI品質、費用、復旧/競合を証跡で示す。

Workers中心のモジュラーモノリス、D1業務正本、R2非公開添付、Google Maps、Workers AI/Jev/LLM、PWAを使用。候補基盤/版は02/14で検証する。複数分団拡張のためunitと認可境界を残すが本格テナント基盤を当初から増設しない。

正式指令/119/現場指揮/常時GPS/AI設備使用可否の自動確定/無許諾実情報公開は対象外。実災害用途の具体境界とGoogle契約適合はD08、既存連絡手段を維持する。デモ/実運用は分離し、開発中のプレビューを正式リリースと呼ばない。正式条件13、未決14、レビュー対応15を参照。
