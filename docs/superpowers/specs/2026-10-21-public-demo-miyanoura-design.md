# 公開営業デモ（宮之浦ベース架空分団）設計書

版: v1.1 / 2026-10-21 / ブレインストーミング（ユーザーとの対話）とビルダー検読を経て作成。§8の4項目はユーザー確定済み。承認待ち。

## 1. 目的（なぜやるか）

FireOSの開発は完成（T001〜T088・架空データ・ローカル検証）。正式リリースには実団体の回答（D01〜D20）と実環境確認が要るが、その前に**営業活動として、まず少数の特定の相手（消防団関係者）に自分のスマホで実際に触ってもらい、反応を見ながら提案を進めたい**。

そのための道具として、**公開URL・体験アカウント・宮之浦（屋久島）が舞台の架空分団データ**を備えた常時稼働のデモ環境を作る。正式リリース判定（docs/13 RG-01〜10）とは独立の営業用の位置づけで、docs/13 §5「完成したアプリを消防団へ提案」の流れの実行部にあたる。

**営業で最初に響かせる場面（コントローラの判断・ユーザー委任）**: 相手のスマホに宮之浦の見慣れた地理と架空の消火栓・防火水槽が出る**地図**。続く実操作は**点検登録（写真付き）→異常の起票→AI分類の提案**の3分。

## 2. 目標

1. Cloudflareのdemo環境（`fireos-demo`）へデプロイ済みで、スマホのブラウザから常時アクセスできる（URLは直渡し・QR）
2. 体験アカウント3本（管理者・幹部・一般団員）を**パスワードだけでログイン可能**（二要素認証なし・固定の認証情報）
3. デモデータは宮之浦ベースの架空分団（規模は現行デモと同等: 団員16名程度・施設13件程度＋地図映えの配置）
4. **Google Maps実地図の実装**（現在地図面はプロトタイプと同じ置き換え絵=T021/X-V05残り。キーがある環境では実地図＋マーカー、無い環境〔ローカル・試験〕では現行の置き換え絵にフォールバック）
5. 書き込みは自由に触ってもらう。**週次の自動リセット＋営業前の手動リセット**で常に綺麗な状態を保つ
6. 公開に伴うセキュリティ実設定（WAF/Rate Limiting層・security headers。ops/demo-deploy.md §5.3の手順実行）
7. 営業台本1枚（docs/DEMO_SCRIPT.md: 5分の動線と口上。アプリ内「使い方ガイド」・docs/USER_GUIDE.mdは既にある）

## 3. 非目標（やらないこと）

- 正式リリース判定（RG-01〜10）を満たすこと／D01〜D20の回答を得ること／実データを入れること
- 不特定多数へのURL配布・新規登録（サインアップ）の開放・営業相手ごとのデータ分離（共有1環境）
- Google Maps以外の新機能開発・UIの大幅変更
- 実Cloudflareでの性能計測や復元演習などX-V0*の検証手順（デモ稼働の副産物で自然に得られるものは記録するが、網羅はしない）

## 4. 反目標（これを犯したら失敗）

- 実在の水利位置・実名簿・実写写真をデモへ載せる（AGENTS.md。施設は架空の点・名前・番号で、背景の地理だけ実物）
- デモ環境と将来の本番環境の境界を曖昧にする（RG-09の分離規律・verifyDemoIsolation・check:environmentを維持）
- 「承認済み」「正式版」と誤読できる表示（「架空データによる検証版」バッジを維持）
- 費用の枠を超える常時稼働（Demo用のbudget上限〔月$5・AI 500回/日等〕・Maps月2,000ロード制限の維持）

## 5. 制約

- 架空データのみ。demo環境のbinding/Secret/データは他環境と分離（wrangler.jsoncの4環境構成・TEST_AUTH等はdemoへ入れない）
- 既存資産を再利用: seedDemo／verifyDemoIsolation／DEMO_SECURITY_POLICY／config/budget-development.json／ops/demo-deploy.md §5の手順
- 認証: 招待フローのe2eで `mfa:false` の受け入れ実績あり＝パスワードのみの体験アカウントは現行の仕組みで作れる
- Maps: Google Maps JavaScript API・キーはリファラ制限・帰属表示あり・ops/demo-deploy.md §4.3の枠管理
- ユーザー作業（コード以外）: Cloudflareアカウント（Workers Paid $5/月）・Google Mapsキー（請求先付き）・wrangler login・Secret登録

## 6. どう作るか（決まっている部分。「私の判断」と明示したものはユーザー承認対象）

| 部品 | 内容 |
|---|---|
| 地図の実装〔本設計の柱〕 | Google Maps JS API読み込み＋`FacilityMarkers`/操作（種別チップ・選択シート・一覧・外部地図アプリ経路）を実地図上へ。**キーが無い環境では現行の置き換え絵のまま**（ローカル・試験・e2eは不変＝X-V05の「実接続」を壊さない）。prototypeの見た目（Design System）に従う |
| 宮之浦データ | seedDemoのデータセットを差し替え。座標は宮之浦周辺（実地理の範囲内）に**架空の点**を分布（川・港・国道沿いを意識して地図映え）。施設名・管理番号・団員名・様式は架空 |
| 体験アカウントとMFA | seed時に3本を固定の認証情報で生成（メールアドレス形式の固定ID・パスワード・MFAなし・役割付与）。**認可規則（PER-06/07/08の二要素必須）は変えない**。二要素が要る操作（団員の登録/変更・招待/停止/権限・監査/費用/AI評価の閲覧）は営業台本に含めず、体験アカウントでそこへ触れると画面に「二要素認証が必要」と出る挙動は**セキュリティの説明材料**として台本に明記する。営業担当が実演したい場合だけMFA設定済みの自分用管理者アカウントを使う〔私の判断〕 |
| リセット | ①seed CLIの `--remote` 対応（demo環境のD1/R2へ再投入・X-DEMO残作業④）②GitHub Actionsの週次workflow＋手動dispatch③手順はops/demo-deploy.mdへ追記 |
| デプロイ | ops/demo-deploy.md §5.1の手順実行（資源作成→migration→bootstrap管理者→seed→URL確定）。**URLはユーザー取得の独自ドメイン**（§8-1）。AUTH_BASE_URL等の実URLに変わる設定も更新 |
| セキュリティ実設定 | ①WAF/Rate Limiting層は取得した独自ドメイン（zone）へ設定（ops/demo-deploy.md §5.3どおり）②**SPAへのCSPは今回つける**〔私の判断〕: Google Maps読み込みに必要な外部ドメイン（maps.googleapis.com・gstatic・fonts等）を許可リストへ。デプロイ後の実URLで「地図・点検・AI・出欠」動線の動作確認を営業前チェックリストへ含める（許可漏れで地図が白紙になる事故を防ぐ）。ローカル・試験のe2eは現状維持 |
| ユーザー作業手順書 | opsへ「デモ用アカウント・契約の手順」を作る（Cloudflareアカウント・Workers Paid・ドメイン取得・Google Mapsキー発行〔参照元制限〕・wrangler login・Secret登録・Maps割当の確認）。公式ドキュメントを確認しながら作成し出典を付ける（§8-3） |
| 営業台本 | docs/DEMO_SCRIPT.md（5分: 地図→点検登録→異常/AI→出欠→締め＋「二要素が要る機微操作」の説明材料）。QRコード（URL直渡し用）の生成手順も含める |
| 台帳 | docs/16へ営業デモ準備のタスクを追加（実装・試験・証跡の規律を維持） |

## 7. 作る人に残す部分

- Google Maps実装の技術細部（読み込み方式・`@types/google.maps`・SW干渉回避〔sw.tsは既にGoogle系を対象外と認識済み〕・キーの環境変数受け渡し・置き換え絵フォールバックの条件分岐の切り目）
- 宮之浦データの具体（座標群・名前・番号・写真は既存の架空写真資材を再利用）
- 体験アカウント生成の実装経路（better-authのuser/account行の直接作成 or 招待APIの一括実行＋パスワード固定化。固定パスワードの強度と漏洩時の影響はデモ環境限定で許容する旨をopsへ記録）
- 週次リセットworkflowの実装（CI権限・失敗時の通知）
- デプロイ実行の段取り（ユーザーのCloudflare/Google作業を挟む順序）

## 8. ユーザーの決定（2026-10-21 確定）

1. **独自ドメインを取る** — WAF/Rate Limiting・Mapsキーの参照元制限・営業URLの見栄えのため。ドメイン取得はユーザー作業手順書に含める
2. **団体名は実名「宮之浦分団」** — 画面の「架空データによる検証版です」バッジとデモ台本で実データでない旨を必ず併記する
3. **Cloudflare・Google Mapsの契約はユーザーが自分のアカウントで実施** — 最初の成果物として**ユーザー作業手順書**（アカウント作成・カード登録・ドメイン取得・Maps APIキー発行・wrangler login・Secret登録）を作る。**手順は公式ドキュメントの該当節を確認しながら作成し、出典と確認済み日を明記する**（ユーザー要求）。不明点は推測して書かず公式情報の出典を付ける
4. **週1回の自動リセットで確定**（営業前の手動リセットはいつでも可）
