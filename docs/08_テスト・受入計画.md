# 08 テスト・受入計画（ドラフト）

## 1. テスト方針

- P0の業務フロー・認可・データ整合性を先に検証する。
- 画面の正常系だけでなく、通信断、重複送信、権限エラー、誤座標、未確認情報を必ず試験する。
- Cloudflare/Google Maps/AIの外部依存はモック・ステージング・限定実アクセスを使い分ける。
- AIの品質試験はP1の採用条件とし、MVP完了をAI導入に依存させない。

## 2. テスト区分

| 区分 | 目的 | 実施方法の例 |
|---|---|---|
| 単体 | 入力検証、日付・期限計算、ロール判定 | Vitest等 |
| API結合 | Hono/Drizzle/D1/認証の接続 | テストDBでのAPI試験 |
| UI/E2E | 実際の画面遷移・フォーム・マップ表示 | Playwright等 |
| セキュリティ | 認可、IDの横取り、添付URL、秘密情報流出防止 | ネガティブテスト |
| 性能 | 基本API p95、地図の表示件数、AI処理時間 | ステージングで計測 |
| 運用 | 復元、障害対応、請求異常の確認手順 | 手順書に沿った演習 |
| AI評価 | 日本語分類、未知表現、誤分類、文章の事実一致 | 人手ラベル付きテスト集合 |

## 3. 主要受入シナリオ

| TC-ID | 要件 | シナリオ | 期待結果 |
|---|---|---|---|

| TC-09 | MAP-05/06 | 施設に点検記録・写真を追加する | 施設詳細に正しい履歴が表示 |
| TC-10 | MAP-07 | 未確認報告を登録する | 確認済み情報として表示されない |
| TC-11 | AST-01/02 | 車両の台帳登録と点検 | それぞれの対象に履歴を保持 |
| TC-12 | DSP-01/02 | 模擬出動を登録し参集記録を更新 | 実出動と区別され、参加状況を参照可 |
| TC-13 | DOC-01 | 非公開添付を他人のIDで参照 | 閲覧権限がなければ取得できない |
| TC-14 | AUDIT | 台帳更新、承認、権限変更 | 操作者・対象・日時等が記録される |

`AUDIT`は要件定義「監査ログ」の横断要件を指す仮ラベル。正式な要件IDはv0.2で追加する。

## 4. AI評価ケース（P1）

### Jevの分類

| 例文（すべて架空） | 期待される人手ラベル |
|---|---|
| 「消火栓の蓋が固くて開閉に時間がかかった」 | equipment_issue |
| 「格納箱の前に資材が置かれていた」 | access_obstruction |
| 「格納箱内のホースが一本足りない」 | missing_equipment |
| 「異常は見つからなかった」 | no_issue |
| 「蓋は問題ないが周辺が塞がっている」 | access_obstruction（否定表現の確認） |
| 「よく分からなかったので次回もう一度調べたい」 | needs_manual_review |

- 複数該当、曖昧語、誤字、方言、否定、長文、ノイズを含むケースを追加する。
- モデルが答えを返せない場合に手動確認に切り替わることを検証する。
- クラス別適合率・再現率・マクロF1と、要確認の見逃し件数を計測する。
- 精度の合格閾値は、実データと業務リスクの確認後に設定する。

### LLM文書生成

- 入力に終了時刻がなければ推測せず「未入力」として扱う。
- 入力に存在しない出動人数や設備異常を捏造しない。
- 承認前に正式な帳票として配信・公開しない。
- モデル停止時にも手入力で記録を完成させられる。

## 5. セキュリティの回帰試験

- 他分団/他ユーザーのIDをパスに指定してアクセスできないか。
- 非公開写真の取得URLを第三者へ転送しても長期間使用できないか。
- 退団・無効化したアカウントの旧セッションが有効でないか。
- ログにAPIキー、セッショントークン、住所、AIへの機微な入力内容が露出しないか。
- 公開デモが本番のAPI・DB・ストレージへ接続しないか。

## 6. MVP完了判定

P0の要件IDと本書TC-01〜TC-18を対応付け、優先度の高い項目が通過した時点でMVPとする。未通過項目は影響と回避策を記録する。**実災害での安全な利用を保証する受入試験ではない**ことを明記する。

## 7. 試験の成果物

- テストケース一覧、実行日、環境、結果、証跡
- 不具合一覧（重要度、再現手順、修正状況）
- AIモデル比較表と誤分類例（P1）
- セキュリティ・権限制御の検証結果
- 復元試験の記録
