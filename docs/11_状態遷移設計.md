# 11 状態遷移設計

版：v0.3 / 2026-10-13 / B案・未承認。状態コードとDB/API/UIの意味の正本。業務承認者・締切・点検基準は14で決定する。

## 1. 共通契約

状態は自由文字列でなく列挙/CHECKで制約する。変更要求は`version`・必要理由・前提状態を含み、サーバーが遷移とPERを検査する。未知状態は400、許可外遷移は422、旧版は409、認可失敗は403/404。成功時だけ状態履歴と監査を同一D1単位で追記する。訂正理由を残すが、個人情報本文を監査へ複製しない。

## 3. 訂正・取消

原本点検・実績版・承認記録・監査はUPDATEで書換えない。新訂正レコードに`supersedes_id/reason/actor/at`を持ち、現在版pointerの切替もversionガードする。既に解決した異常の訂正で自動再開/削除しない。担当者に再確認タスクを作る案としD07で確定する。取消も過去の参加/配送/使用履歴を消さず、集計は無効なoperationを除く。

## 4. 状態に依存する試験

正常な各辺、未許可の逆辺、旧version、別担当、二重承認、元版変更、途中SQL失敗をCT-01〜06/ATの該当要件で検証する。送信/処理状態と現実の事実（実到着・安全・設備使用可否）を同一視しないUIをAT-MAP-07/AT-COM-02/AT-DSP-02で確認する。
