# FireOS 操作説明（利用者向け）

消防団の管理者と団員のための、FireOSの簡単な操作説明です。画面の名前と操作は、いま動いているアプリそのものに合わせています。詳しい設計や運用の決まりごとは別の文書（docs/・ops/）にあり、本書は操作の案内だけを扱います。

**対応する画面・端末**: スマホ（狭い画面。画面下の「ホーム／マップ／予定・活動／AI／メニュー」の5つのタブで移動）とPC（左のサイドバーで移動。スマホの「メニュー」タブにある機能は、PCではサイドバーの「タスク・通知」「管理」などのグループに並んでいます）。ブラウザで動き、圏外でも一部の操作ができます（§7）。

**大事な原則を先に3つだけ**:

1. **正式な指令・連絡は、いままでどおり既存の系統（無線・電話・連絡網・口頭）が正**です。FireOSの通知は記録と補助のためのものです（各画面にもこの注記があります）。
2. **AIが決めることはありません。** 異常の分類や帳票の下書きを提案することはありますが、確定・送信・承認は必ず人の操作です（§5）。
3. **最初の登録は招待制です。** 自分で新規登録はできません。分団の管理者から招待を受け取ってから始めます。

## 1. 導入（はじめて使うとき）

**はじめてログインする（招待を受け取ったら）**

1. 管理者から受け取った招待のリンク（`https://＜団体のURL＞/login#invite=…`）を開きます。リンクには期限があるため、早めに済ませます。誰にも転送しません。
2. 招待のメールアドレスと、パスワード（12文字以上）を入力して登録します。
3. 続けて**二要素認証**を設定します。認証アプリ（スマホのアプリ）で表示される6桁のコードを入力して確定します。
4. **回復コード**（8個）が表示されるので、紙など安全な場所に書き留めます。認証アプリを失ったときの代替手段で、1つのコードは1回だけ使えます。

**いつものログイン**

1. ログイン画面でメールアドレスとパスワードを入力します。
2. 認証アプリの6桁の数字を入力します。認証アプリが使えないときは「回復コードを使う」に切り替えます。

**パスワードを忘れた・変更したい**

1. ログイン画面の「パスワードの再設定」から進めます（再設定の案内を受け取る手段は、団体の運用によって異なります。届かない場合は管理者へ連絡してください）。
2. 変更に成功すると、他の端末のログインは自動的に解除されます。

## 2. 通常利用（ホーム・出欠・名簿・お知らせ）

**ホーム（最初の画面）**

- これからの予定・本人未回答・確認待ちの異常・点検期限・通知・自分のタスクが数字で並んでいます。
- 数字のタイルを押すと、その内容の一覧が開きます（数字と一覧の件数は一致します）。

**活動の出欠を回答する**

1. 「予定・活動」の一覧から活動を開きます。
2. 「参加」「不参加」「未定」のいずれかで回答します（締切が過ぎると回答できなくなります）。
3. 家族など**代理で回答できるのは、許可された役割の人だけ**です。代理回答のときは理由が必須です。
4. 活動が終わったあとの記録では、予定の「参加」と実際の「実参加」は別々に表示されます。実績の入力は活動の詳細画面から行います（担当者）。

**名簿を見る・団員を管理する（管理者）**

1. スマホは「メニュー」タブの「団員名簿」、PCはサイドバーの「団員」を開きます。
2. 検索で絞り込んで団員を開き、所属・役職・許可項目を確認できます。登録・変更・停止は管理者の操作です。

**お知らせを読む**

1. 「お知らせ」（スマホは「メニュー」タブ）を開きます。自分が対象のお知らせだけが並びます。
2. 項目を開いて「内容を確認」で既読になります（既読は見た人の記録として残ります）。
3. 内容が改訂されて新しい版が出ると、もう一度確認する必要があります（既読の表示が戻ります）。

## 3. 点検（施設・資機材・異常・訂正）

**施設を点検する**

1. 「マップ」で施設を探します（種類のチップ〔消火栓・防火水槽・資器材箱〕で絞り込む、管理番号で検索、一覧に切り替える、のどれでもよい）。
2. 施設を開き（スマホは行をタップ、PCは右の一覧から選択）、「点検する」を押します。
3. 点検様式を選び、項目ごとに結果（良好・異常あり など）を入れます。
4. 「写真・メモへ進む」で写真とメモを添え（写真は検査が済んだものだけ添付できます）、「確認へ進む」で内容を確かめ、「点検を保存」します。
5. **「異常あり」で保存すると、この記録を起点に異常の報告が自動で作られます**（施設の状態は「異常報告あり」に変わります）。画面の確認画面でも、異常の報告が作られるかどうか事前に示されます。

**車両・資機材を点検する**: 「車両・資機材」から対象を開き、施設と同じ流れで点検します。

**異常の報告を見る・進める（担当者・管理者）**

1. 「点検管理」（スマホは「メニュー」タブ）を開きます。異常は「確認待ち → 確認中 → 対応中 → 対応実施 → 終了」と進みます。
2. 項目を開くと、起点となった点検・担当・理由・履歴が並びます。

**点検の記録を訂正する（間違えて保存したとき）**

1. 施設（または資産）の詳細の点検履歴から、訂正したい記録を開いて「訂正」します。
2. **元の記録は消えず、残ります**。訂正として新しい記録が追加され、施設に表示されるのは現在の記録です。

## 4. 通知（受け取る・送る）

**通知を受け取る・既読にする**

1. ホームの「通知」または「設定・通知」（PCは「タスク・通知」）を開きます。自分宛の通知が未読順に並びます。
2. 通知の状態は「受付済み」「到達不明」「既読」のように区別され、**届いたかどうか分からないものは「到達不明」と正直に表示されます**。
3. 既読にするのは、通知を開いて「内容を確認」を押す操作です（開いただけでは既読になりません）。
4. 通知は「正式な連絡は既存の系統」の注記とともに表示されます。災害時の指令はFireOSだけで完結しません。

**通知を送る（作成できる役割の人）**

1. 「設定・通知」から通知を作成します。元になる情報（活動など）を選び、本文と対象者を決めて下書きを保存します。
2. **送信は人の承認が必要です。** 下書きを開くと承認前の確認（本文・対象・人数）が出るので、確かめて「承認する」を押すと対象者への配送が始まります。やめるときは「取消する」です（取消は誰にも届く前に限ります）。
3. 承認後は配送結果（受付済み・失敗・到達不明）を確認できます。「到達不明」があったら対象者に直接確認してください（画面にも案内が出ます）。

**承認せずに離れた下書きを再開する**

1. 「設定・通知」の「送信した通知」に切り替えます。自分が作った通知（未承認の下書きを含む）が並びます。
2. 未承認の下書きを開くと、承認前の確認からやり直せます（承認または取消）。

## 5. 承認（AIの提案・帳票 — 人の承認が必要な操作）

FireOSで**人による承認・確定が必須**な操作は、次のとおりです。AIや機械だけでは確定しません。

**AI提案（異常の分類）を承認する（担当者・管理者）**

1. 「AIレビュー」（スマホは「メニュー」タブ）で「AI分類を依頼」すると、AIが異常の分類と対応の候補を出します。
2. 候補を開くと原文（点検の記録）と提案内容が並び、**差分を確かめてから**「修正して承認」で確定します（分類の修正・タスクの担当指定もここで行います）。不要なら「却下」します。
3. 提案が古くなっているときは、承認できず、やり直しを求められます（古い提案を無理に承認させません）。

**帳票（活動記録）を承認する（承認できる役割の人）**

1. 活動の詳細（または「活動記録」）から報告書の生成を依頼します。AIが下書きを作ります（この環境でAIが使えないときは「手動で作成」できます）。
2. 下書きの不足欄を埋めて保存したら、「承認」で版を確定します。**出力（PDF等）できるのは承認された版だけ**です。
3. 修正は新しい版として作り、承認し直します（承認済みの前の版も履歴に残ります）。

**そのほか承認が要るもの**: 点検様式の新しい版（管理画面で承認）も同じ考え方です。承認の記録はすべて監査に残ります（誰が・いつ・何を）。

## 6. AIアシスタント（参考）

- 「AI」タブのアシスタントには、自分の権限の範囲で予定・点検・記録について質問できます。回答には出典（引用した記録）が必ず付きます。
- アシスタントが書き込みや通知を提案することはあっても、実行は人の確認を経ます。

## 7. 通信断（圏外・つながらないとき）

- **圏外でも入力を始められます。** 点検や出欠の入力は端末に一時保存（端末下書き）され、通信が戻ったときに自動で送られます。
- 保存の結果が確認できなかったときは、**「保存しました」とは表示しません**。「結果を確認できません」のような正直な表示が出て、入力は端末下書きに残ります。
- 通信が戻ったら、スマホの「メニュー」タブの「同期の状況」で送信状況を確認できます。「同期待ちの入力はありません。」と出れば、すべて届いています。
- 通信断のときも**正式な連絡・報告の経路は既存の系統**（無線・電話・連絡網）を使ってください。FireOSは記録が戻ってから追いつきます。

## 8. 復旧（通信が戻った・競合したとき）

**同期の再開**

1. 通信が戻れば、端末下書きは自動で送られます。確実にしたいときは「同期の状況」で「反映〇件／競合〇件／拒否〇件」の内訳を確認します。
2. 「応答不明」（サーバーに届いたか分からないもの）は、そのままにせず「同期の状況」から再送または削除を選べます。削除してもサーバー側の結果は変わりません（届いていた記録は残ります）。

**競合（同じものを別の端末で変更したとき）**

- **最後に書いた人が勝つ、ということはありません。** 後からの変更が前の記録とぶつかると「競合」として示され、確認してから処理します。前の記録が黙って上書きされることはありません。

**障害時の代替連絡**

- FireOS全体が使えないときも、**正式な連絡は既存の系統で行います**。紙や電話での運用に切り替える手順は、団体で定めた連絡方法（連絡網）に従います。復旧後は、FireOSに記録を入力し直して、件数の照合を行います（この作業は管理者の案内で行われます）。

## 9. 困ったとき

| 状況 | 何をするか |
|---|---|
| 招待のリンクを開けない・期限が切れた | 管理者に再発行を依頼する（リンクには期限があります） |
| ログインできない（「このアカウントはまだ利用できません」） | 招待の受領が済んでいないか、停止されている可能性があります。分団の管理者へ連絡してください |
| 認証アプリが使えない | ログイン画面の「回復コードを使う」。回復コードも失ったら管理者へ連絡（ops/account-recovery.md の手順で復旧します） |
| 端末を紛失した | すみやかに管理者へ連絡。管理者がその端末のログインをすべて解除します |
| 保存しても「結果を確認できません」のまま | 「同期の状況」で再送してください。解決しなければ管理者へ |
| 通知が届かないと言われた | 送信者は「送信した通知」の配送結果で「到達不明」を確認し、既存の連絡手段で直接確認してください |
| 画面の操作が分からない | この説明書（docs/USER_GUIDE.md）を見るか、管理者へ聞いてください |

**管理者・運用担当向け**: ログイン・招待・権限の復旧手順は `ops/account-recovery.md`、障害時の対応は `ops/outage-runbook.md`、外部障害時の代替運用は `ops/contact-flow.md` にあります。公開デモの運用は `ops/demo-deploy.md`、アカウントの招待と二要素の規則は `ops/bootstrap-admin.md`・`ops/admin-handover.md` にまとまっています。
