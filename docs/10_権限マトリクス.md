# 10 権限マトリクス

版：v0.3 / 2026-10-13 / 未承認設計。技術的強制規則は本書、業務権限の承認は14 D02/D03/D05/D07/D08を正本とする。

## 1. 認可判定

認可は **有効セッション AND 利用可能ユーザー/団員 AND 所属一致 AND 操作権限 AND 対象範囲 AND 項目許可 AND 状態前提**。どれか不明なら拒否する。unitId/actorId/roleはリクエストの自己申告から決定しない。複数ロールは許可の和集合を候補とするが、利用停止・対象外所属・機密項目禁止を優先する（B案、D03）。システム管理者という理由だけで非公開実出動や名簿全文を常時閲覧できるとは確定しない。

担当は`scope_assignments`で団員×対象種別×対象ID×操作セット×有効期限を保持する。APIは親活動/施設/資産/文書の所属・割当をたどり、存在するIDだけで許可しない。所属が違う団員・添付・資産の関連付けも拒否する。将来の複数所属は現在のアクティブunit選択＋所属検査を拡張する。

## 3. 項目の投影

| 区分 | 例 | レスポンス・検索・出力 |
|---|---|---|
| BASIC | 施設番号/目印、予定名、業務上の表示名 | 所属/対象者フィルター後に必要項目だけ返す |
| PERSONAL | 連絡先、私的住所、参加理由 | D02で列を許可。未承認列は収集/返却/索引化しない |
| SENSITIVE | 非公開地点、実出動概要、現場写真 | D08/D09の限定範囲。通常地図と同じ公開範囲とは限らない |
| SECURITY | password hash、session token、招待token hash | 業務DTO/監査本文/AIに一切出さない |
| DERIVED | 未回答数、未解決件数、AI要約、検索スニペット | 許可された元行だけから算出。件数や引用から漏らさない |

一覧/詳細/地図/CSV/帳票/ダッシュボード/添付/RAGは同じ政策関数を使用する。SQLで対象行を絞ってからページング・集計し、全件取得後にUIで隠す方式は禁止。対象外IDは404に統一する案、既知対象の操作不可は403。両者の存在情報をログで漏らさない。

## 4. 権限変更・承認競合

`users.authz_version`を変更トランザクションで増加。認可した版を書込ガードでも照合し、権限変更と承認が競合したら再認可する（02）。セッションCookie cacheは業務APIでは使用せず、最新状態を読む。招待/失効など認証DBとの境界は07。

添付取得は新規リクエストごとに元対象ACL＋検査済状態を検査する。複数対象へ共有した添付の許可判定は「閲覧可能なリンクが一つ以上」案だが、機微情報を低権限対象へリンクする操作を禁止し、分類の引下げは自動で行わない。

RAGは検索前フィルター＋生成前再検査＋引用取得時再検査。文書削除/ACL変更後の旧回答は再取得時に引用をマスク/回答失効し、過去の閲覧許可を永続権限とみなさない。モデルや管理者UIには認可の迂回経路を作らない。
