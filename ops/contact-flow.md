# 正式連絡の系統・紙/既存電話への切替・復帰照合の手順（T084）

目的: **災害時の正式な指令・連絡・安否確認は既存の責任系統（消防署・団長からの指令、電話・無線・既存の連絡網）で行い、FireOSを唯一の系統にしない**ことを運用として固定する。アプリや回線が使えないときは紙と既存の電話に切り替え、復帰後にアプリへ入力して照合する。正本は docs/07 §1/§5、docs/14 D08（実災害用途・正式連絡）/D17（管理主体・窓口）。**具体の連絡手段・責任者・様式はD08/D17未決**のため、本書の役割名・様式は検証用の提案（架空）であり、承認済みではない。

**現状の正直な限界（2026-10-19時点）**: §4の切替と§5の復帰照合は**架空の机上演習（下記の想定シナリオ）**として記述したもの。アプリ側の観測（注記の常時表示・到達不明の表示・同期結果照会）はローカルのe2eで確認済み（docs/evidence/V07-outage.md）。**実在の人・実際の電話/紙を使った切替演習は未実施**（提案時TODO）。

## 1. 系統（だれが・何で・何を伝えるか）

| 連絡 | 正式な系統（正） | FireOSの役割（補助） |
|---|---|---|
| 出動の指令 | 消防署・団長からの指令（既存の電話・無線・サイレン等） | 出動の**記録**（模擬/訓練/実出動記録の区別）と参集状況の共有。指令文の送信はしない（出動登録は「正式な指令ではありません」と表示） |
| 招集・参集の確認 | 分団の既存連絡網（電話の順送り等） | 参集の記録（本人/代理）。到達・応答の保証はしない |
| 安否確認 | 既存の系統（D08/D17で決める責任者） | 扱わない（既読≠安否） |
| 平常の連絡（訓練日程・点検依頼） | 既存の連絡網と併用 | 通知（承認つき）。受付・到達不明・既読を別に表示 |

画面上の表示（ローカル演習で全画面を確認）: 出動一覧・出動詳細は「この記録は正式な指令ではありません。現場の指揮は団長・消防署の指示に従ってください。本アプリは応答と記録の共有のための補助です。」、通知一覧・通知の承認前確認・配送結果・通知詳細は「災害時の正式な連絡は、既存の連絡網（電話・無線など）で行ってください。この通知は補助であり、受付や既読は連絡の完了・安否の確認を意味しません。」

## 2. 到達不明・未読の人への対応

1. 通知の配送結果で「到達不明」が出たら「結果を確認」で氏名を見る（ops/outage-runbook.md §2.5）。
2. 幹部が**既存の電話・対面**で本人へ直接伝える。アプリで同じ通知を作り直して再送しない。
3. 伝えた結果は連絡記録票（§3の様式C）へ。アプリの「到達不明」表示は消さない（到達したことにしない）。

## 3. 手動帳票（紙）の様式（架空の提案。正式様式はD20/D08の後）

事前に各詰所・幹部の手元に印刷しておく。記入は**後でアプリへ入力できる粒度**にする。

| 様式 | 用途 | 欄 |
|---|---|---|
| A 参集記録票 | 出動・訓練の参集 | 出来事の種別（模擬/訓練/実出動記録）・発生日時・団員氏名・状態（参集中/現着/帰還/参集不可）・時刻・記入者 |
| B 点検記録票 | 水利・資機材の点検 | 施設の管理番号（または識別名）・種別・点検日時・実施者・結果（良好/異常あり/未確認）・異常の内容・写真の有無 |
| C 連絡記録票 | 到達不明の直接確認・紙/電話での連絡 | 日時・連絡した人・相手・手段（電話/対面/無線）・内容・返答 |
| D 活動実績票 | 報告書の元 | 活動名・実施日時（開始/終了）・場所・参加者・内容。報告書はアプリ復帰後に「手動で作成」で入力 |

施設の管理番号・座標は、地図が使えないときのためにマップの「一覧」（ops/outage-runbook.md §2.1）を印刷するか、施設CSV書き出し（施設CSV取込の画面の「現在の台帳を書き出す（CSV）」）で控える。**非公開水利を含む紙は保管場所と廃棄を管理主体が決める**（docs/07 §1。実データの扱いは了承後）。

## 4. 切替の手順（アプリ・回線が使えない、または災害時）

1. **判断**: 分団長（管理主体）が「紙・既存電話に切替」を宣言する。正担当管理者（不在なら副担当）がアプリの状態（ログインできるか・保存できるか・通知の到達不明の多さ）を報告する。
2. **周知**: 既存の連絡網で「アプリの記録は後でまとめて入力する。連絡は電話・無線で」と伝える。アプリの通知で周知しない（届かない可能性があるため）。
3. **記録**: 各自・記録係が§3の様式に記入する。アプリが部分的に使える場合でも、正式な連絡は既存の系統のまま。
4. **端末の入力が残っている人**: 端末に「同期待ちの入力」があっても消さない（同期の状況 `/app/sync`。ログアウトすると端末の下書きは消える＝T075の仕様。**未同期のまま回収しないでログアウトしない**）。

## 5. 復帰照合の手順（アプリ・回線が戻った後）

1. **同期の照会**: 各自がアプリにログインし、「同期の状況」（`/app/sync`）で「今すぐ同期」→「同期待ちの入力はありません。」を確認。競合・拒否が残った人は記録係へ申告（自動上書きはしない）。
2. **紙からの入力**（記録係。二者で読み合わせ）:
   - 様式A → 出動詳細（`/app/incidents/<id>`）の参集の記録（代理の記録は理由つき）。
   - 様式B → 施設詳細の「この施設を点検する」から点検登録。
   - 様式D → 報告書（`/app/reports?activity=<活動ID>`）の「手動で作成」。
   - 様式C → アプリには入れない（連絡記録は紙で保管。到達不明の表示はそのまま）。
3. **照合**: 紙の件数とアプリの件数を突き合わせる（参集者数・点検件数）。**二重入力の確認**: 端末から同期された記録と紙から入力した記録が同じものでないか（同じ団員・同じ時刻）を見て、重複は訂正（点検は訂正の版、参集は状態の更新）で直す。削除はしない（履歴は残る）。
4. **記録**: 照合の結果（件数・差異・訂正）を連絡記録票の末尾に書き、分団長が確認する。

想定: 架空市で大雨。19:00 正担当管理者の端末が水没（不在扱い）、19:10 回線が不安定でアプリの保存が「結果を確認できません」になる。

| 時刻 | 起きたこと | 対応（本書・関連runbookの節） | 担当 |
|---|---|---|---|
| 19:00 | 正担当の端末水没の申告（電話） | ops/admin-handover.md §3: 副担当が本人確認→正担当の全セッション失効 | 副担当管理者・分団長 |
| 19:05 | 消防署から出動指令（無線） | 指令は無線のまま受ける。アプリには模擬ではなく実出動の**記録**を後で作る（§1） | 分団長 |

| 翌日 | 正担当が新端末で復帰 | ops/admin-handover.md §3-4: 監査ログで代行中の操作を確認 | 正担当管理者 |
